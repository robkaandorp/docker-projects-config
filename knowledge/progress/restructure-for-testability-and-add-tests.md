### coder (narrative)

I restructured docker-volume-rbd into four modules: an injectable Rbd (CommandRunner + FileSystem defaults), a pure parseConfig, a createApp factory with a per-call mountPointTable and a Pick<Rbd,...> interface, and a thin server entry point. Since I could not diff-verify equivalence by reading alone, I built a throwaway end-to-end harness that compiled the OLD sources from the merge base, ran old and new server processes side by side on the real plugin socket with fake rbd/mount/mkfs binaries, and deep-compared both HTTP responses and recorded CLI argv across six environment configs (22 CLI calls each, plus a failure-injection case) — all identical. My main struggles were self-inflicted scratch-harness bugs, not product bugs: a shell redirection scope mistake (`printf ... >> log` only redirected the last command) meant argv leaked to stdout so the first run falsely "passed" with 1 CLI call, and two early assertions were too strict about which errno a missing binary yields in this image. I added non-vacuity guards (asserting >=8 CLI calls, a real mount, an umount and a mkfs per run) so identical-but-empty runs could not pass, then removed every scratch artifact before committing; the frozen-lockfile install and strict tsc build both pass on the committed revision.
