### coder (narrative)

I fully rewrote .github/workflows/docker-image.yml around package.json's version as the single source of truth, with a build job (checkout without persisted credentials, jq-based semver validation, fail-closed already-released guard, buildx, master-only Docker Hub login, conditional build-push of v<version>/latest) and a release job that holds the only contents: write permission, checks out nothing, and runs gh release create with GH_REPO and --target so the tag lands on the built SHA rather than develop's HEAD. Rather than eyeballing the YAML, I extracted the real run: blocks with yq and tested them against a stub gh that mimics `gh api -i` output, which is how I caught two genuine bugs in my first draft: `grep -Eq '^...$'` accepted a newline-containing version (and would have injected extra lines into GITHUB_OUTPUT — fixed with bash `=~`), and classifying errors by grepping "404" in stderr text was unreliable (fixed by parsing the actual HTTP status line, so a port number like :404 can't be mistaken for a not-found). I also built a 57-assertion conformance checker against the spec plus actionlint with shellcheck, a frozen-lockfile install, and a tsc build — all green. Frustrations were purely tooling: no node/pnpm/actionlint/pyyaml preinstalled (installed Node 24, Corepack pnpm, actionlint, shellcheck, yq into /tmp), and my own test harness had several quoting/matching bugs (heredoc escaping, regex brackets, unsupported `yq -c`) that initially produced false failures I had to triage rather than trust.
